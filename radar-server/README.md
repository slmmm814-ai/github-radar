# Radar Server

خادم صغير بلا أي مكتبات خارجية (Python 3.9+). ينزّل أرشيف GH Archive كل ساعة، يعدّ **النجوم والتفرّعات** لكل مستودع، ويقدّم API لتطبيق رادار GitHub+ يكشف **المستودعات المتسارعة قبل وصولها إلى Trending**.

## التشغيل
```bash
export RADAR_KEY="مفتاح-سري-طويل"      # مهم إن كان الخادم على الإنترنت
python3 radar_server.py                  # يجلب في الخلفية ويخدم على المنفذ 8787
```
Docker: `docker build -t radar-server . && docker run -d -p 8787:8787 -v radar:/data -e RADAR_KEY=... radar-server`

اختبار ذاتي ببيانات اصطناعية: `python3 tests/selftest.py`

## واجهة API
كل المسارات (عدا /health) تتطلب الترويسة `X-Api-Key` إن ضُبط RADAR_KEY.
- `GET /health` حالة الجلب وآخر ساعة وعدد الصفوف.
- `GET /trending?window=24&limit=30&min_stars=10&sort=heat` المستودعات حسب نجوم آخر window ساعة. الترتيب: heat (افتراضي) أو stars أو forks أو accel.
- `GET /rising?window=24&min_accel=3` المستودعات التي تضاعفت وتيرتها عن النافذة السابقة.
- `GET /repo/<owner>/<name>?hours=72` سلسلة النجوم والتفرّعات بالساعة.

الحقل `accel` = نجوم النافذة الحالية ÷ max(نجوم السابقة، عدد الساعات). الأرضية ضرورية لأن الساعات تحت العتبة (RADAR_MIN_HOURLY) لا تُخزَّن؛ فالرقم تقدير لا قياس دقيق. وإن غطّت بيانات النافذة السابقة أقل من 80% تصبح `accel` فارغة (`prev_ok=false`).

## المتغيرات
| المتغير | الافتراضي | المعنى |
|---|---|---|
| RADAR_KEY | فارغ | مفتاح الوصول |
| PORT | 8787 | المنفذ |
| RADAR_DB | radar.db | ملف SQLite |
| RADAR_BACKFILL_HOURS | 48 | ساعات الجلب عند أول تشغيل (يلزم 48 لحساب التسارع على 24 ساعة) |
| RADAR_RETENTION_DAYS | 14 | مدة الاحتفاظ |
| RADAR_LAG_HOURS | 2 | تأخير نشر الملف عند GH Archive |
| RADAR_MIN_HOURLY | 3 | أقل نجوم أو تفرّعات في الساعة ليُخزَّن المستودع |

## متطلبات يجب أن تعرفها
- **الشبكة**: الملف الواحد يقارب 100-150 ميغابايت مضغوطًا بحسب ما وجدته منشورًا عن GH Archive (لم أقسه بنفسي). أول تشغيل بـ 48 ساعة = نحو 5-7 جيجابايت، ثم نحو 3 جيجابايت يوميًا. المناسب: VPS أو حاسوب ببيانات غير محدودة، لا الهاتف.
- **المعالجة**: يقرأ الملف بالتدفق دون تحميله في الذاكرة. توقّع من دقيقة إلى عدة دقائق للساعة الواحدة على VPS صغير (تقدير لا قياس).
- **HTTPS**: ضعه خلف Caddy أو Cloudflare Tunnel أو Tailscale. تطبيق الأندرويد يسمح بـ HTTP لتجربة الشبكة المحلية فقط؛ لا ترسل المفتاح عبر HTTP على الإنترنت، وأزل `usesCleartextTraffic` من AndroidManifest.xml في الإنتاج.
- **لم يُجرَّب مع GH Archive الحقيقي**: بيئة الإنشاء لا تصل إلى data.gharchive.org. اختُبر كل المنطق ببيانات اصطناعية بالصيغة نفسها (ملف لكل ساعة بصيغة YYYY-MM-DD-H.json.gz). شغّل `python3 radar_server.py --once` أولًا وراقب السجل.
- **ما لا يجمعه**: لا يعدّ الـ pushes ولا الـ issues ولا يميّز النجوم الآلية. التطبيق يضيف تقييمه وفحوصه فوق هذه الإشارة.
- بيانات GH Archive مرخَّصة ODC-By؛ اذكر المصدر إن نشرت النتائج.
